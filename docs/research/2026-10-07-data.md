Project: categorizer (distill an LLM into a tiny web-page content categorizer).

## 1. Public web corpora

### 1.1 Common Crawl (CC)

**Latest crawl: `CC-MAIN-2026-39`** (September 2026), crawled 2026-09-04 to 2026-09-17.
It has 2.17 B pages, 361.4 TiB uncompressed, 40.4 M hosts, 33.2 M registered domains, and
587.2 M URLs not seen in any earlier crawl. [S1, S2]
The CDX server's `collinfo.json` also lists `CC-MAIN-2026-39` as the newest collection, with
the previous one being `CC-MAIN-2026-34` (August 2026). [S6]

**Cadence:** roughly monthly. The crawl list shows 12 crawls for 2025, and there were crawls
in both August and September 2026. CC publishes no formal schedule. [S3, S6]

**Formats:** [S4]
- **WARC:** raw HTTP request and response plus crawl metadata. Use it when you need the HTML
  for your own extraction, or for replay in a latency test. For 2026-39 the WARCs are
  82.79 TiB compressed in 100,000 files. [S2]
- **WAT:** JSON metadata computed per record (HTTP headers, outlinks). 14.16 TiB. [S2]
- **WET:** CC's own plain-text extraction. 5.89 TiB. DCLM found WET text noisier than
  resiliparse or trafilatura output (see §2). [S2, S20]
- Other listings: `robotstxt.paths.gz` (the robots.txt files CC fetched),
  `non200responses.paths.gz`, `cc-index.paths.gz` (CDX), and `cc-index-table.paths.gz`
  (Parquet). [S2]
- **Truncation erratum:** records are cut at a fetch size limit. The limit was 1 MiB before
  CC-MAIN-2025-13 and 5 MiB from then on. [S2]

**Access:** [S4]
- S3: `s3://commoncrawl/` in us-east-1.
- HTTPS: `https://data.commoncrawl.org/<path>`. No AWS account is needed; plain HTTP range
  requests work.
- Selected crawls are mirrored to a Hugging Face Storage Bucket with the same layout.
- The get-started page contradicts itself on whether S3 API access must be authenticated.
  Use HTTPS to stay simple. **UNVERIFIED which one is current.**

**Columnar URL index (Parquet):** `s3://commoncrawl/cc-index/table/cc-main/warc/`, partitioned
by `crawl=` and `subset=` (`warc`, `crawldiagnostics`, `robotstxt`). [S5]
- Useful columns: `url`, `url_host_registered_domain`, `url_host_tld`,
  `url_host_registry_suffix`, `url_path`, `fetch_status`, `content_languages`, `warc_filename`,
  `warc_record_offset`, `warc_record_length`. [S5]
- Query engines: Athena (the upper bound for one monthly table is about US$1.50), DuckDB
  locally, or Spark (cc-pyspark). [S5]
- `content_languages` holds CLD2 output: up to 3 ISO-639-3 codes per page, for example
  `por`, `eng`, `ind`, `vie`, `tha`. It has been present since CC-MAIN-2018-39. [S7, S8]

How to sample by language and domain (recipe built from the documented columns):

```sql
-- DuckDB / Athena: Portuguese-primary HTML pages, one crawl
SELECT url, url_host_registered_domain, warc_filename, warc_record_offset, warc_record_length
FROM ccindex
WHERE crawl = 'CC-MAIN-2026-39' AND subset = 'warc'
  AND fetch_status = 200
  AND content_languages LIKE 'por%'        -- primary language first in the list
  -- AND url_host_tld = 'br'               -- optional domain/TLD stratification
-- then sample N per registered domain (e.g. ROW_NUMBER() OVER (PARTITION BY domain ORDER BY random()))
```

To fetch a single record:
`curl -r <offset>-<offset+length-1> https://data.commoncrawl.org/<warc_filename>` returns one
gzip member, which you can read with `warcio` or `fastwarc`. Capping pages per domain avoids
a few large sites dominating the sample. That matters for the URL/domain caching experiments.

**CDX server:** `https://index.commoncrawl.org/<CRAWL>-index?url=...&output=json` uses the pywb
CDX API. CC asks users not to overload it and points bulk work to the columnar index. [S6]
`cdx_toolkit` (Apache-2.0) wraps it. [S30]

**Terms of use** [S9]: a limited, non-exclusive, non-transferable license. Crawled content "may
be subject to separate terms of use or terms of service from the owners". Users agree to respect
third-party copyrights. Collecting PII for use outside the crawled content is prohibited. The
user indemnifies CC, explicitly including claims tied to AI training. Disputes go to California
law and JAMS arbitration.
Consequence for this project: a sample of CC is fine for research use. Do **not** republish
page text. Publishing URLs, labels, and derived statistics is lower-risk (judgment call, not
legal advice).

**CCBot and robots.txt:** user agent `CCBot/2.0`. CC tells site owners to opt out with a
robots.txt `Disallow` for CCBot. It publishes its IP ranges at `index.commoncrawl.org/ccbot.json`
and keeps an opt-out ledger. The FineWeb-2 card states that CC respects robots.txt at crawl
time. [S10, S12]

### 1.2 Derived, cleaned corpora

**FineWeb** (`HuggingFaceFW/fineweb`) [S11]
- License ODC-By. English only.
- About 25.9 B rows in the default config, built from CC dumps CC-MAIN-2013-20 through
  CC-MAIN-2025-26 (the newest config listed).
- **Fields include `url`, `dump`, `date`, `language_score`, `token_count`.**
- Sample configs: `sample-10BT` (14.9 M rows), `sample-100BT`, `sample-350BT`.
- Stream it with `load_dataset("HuggingFaceFW/fineweb", name="sample-10BT", split="train", streaming=True)`.
- Text was extracted with trafilatura. **UNVERIFIED on the card page; known from the FineWeb paper.**

**FineWeb-Edu** (`HuggingFaceFW/fineweb-edu`) [S13]
- ODC-By. About 1.3 T tokens and 1.53 B rows.
- Built by keeping FineWeb pages that score at least 3 (on a 0–5 scale) with an
  educational-value classifier. The classifier is based on Snowflake-arctic-embed, trained on
  Llama-3-70B annotations, and the filter removed about 92% of the data.
- `fineweb-edu-score-2` uses threshold 2 and keeps about 5.4 T tokens.
- Has `url`, `score`, `int_score`.
- **Strongly biased toward educational pages.** It under-represents shopping, entertainment,
  sports, and adult pages, so it is a poor source for a taxonomy sample meant to look like ad
  inventory. Use plain FineWeb instead.

**FineWeb-2** (`HuggingFaceFW/fineweb-2`) [S12]
- ODC-By 1.0, and also subject to the CC Terms of Use.
- 96 CC snapshots (summer 2013 to April 2024). About 20 TB, about 5 B documents, over 3 T words.
- 1,868 language–script pairs; 474 have more than 1 k documents.
- **English is excluded** (it is covered by FineWeb).
- **Covers all four target non-English languages:**

  | config | docs | words | disk |
  |---|---|---|---|
  | `por_Latn` | 199.7 M | 109.5 B | 256.9 GB |
  | `ind_Latn` | 100.2 M | 60.3 B | 141.7 GB |
  | `vie_Latn` | 61.1 M | 50.9 B | 121.2 GB |
  | `tha_Thai` | 35.9 M | 24.7 B | 69.9 GB |

- **Fields include `url`, `dump`, `date`, `language_score`, `minhash_cluster_size`, `top_langs`.**
- Each language also has a `_removed` subset holding the filtered-out documents. It is
  downloadable through hub_download but not through load_dataset. It is useful when you want a
  less "clean" sample.
- Stream it with `load_dataset("HuggingFaceFW/fineweb-2", name="por_Latn", split="train", streaming=True)`,
  or use datatrove `ParquetReader("hf://datasets/HuggingFaceFW/fineweb-2/data/por_Latn/train", limit=1000)`.
- PII handling: emails and IPs are anonymized; phone numbers are not.

**mC4** (`allenai/c4`, config per language, e.g. `"pt"`) [S14]
- ODC-By plus the CC terms. 108 languages, 9.7 TB.
- **Fields: `url`, `text`, `timestamp`.**
- Stream it with `load_dataset("allenai/c4", "pt", streaming=True)`.
- Built from CC WET text, which is lower quality. The exact snapshots used are not stated on the
  card. **UNVERIFIED: mC4 used about 71 snapshots per the mT5 paper.**

**CulturaX** (`uonlp/CulturaX`) [S15]
- **Gated:** you must log in and agree to share contact information.
- License: "strictly follows" mC4 (ODC-By) and OSCAR. 167 languages, 6.3 T tokens.
- Built from mC4 3.1.0 plus OSCAR 20.19, 21.09, 22.01, and 23.01, cleaned and deduplicated.
- **Fields: `text`, `timestamp`, `url`, `source`.**
- Sizes: en 3.24 B docs; pt 190.3 M docs (136.9 B tokens); id 23.3 M; vi 57.6 M; th 21.0 M.

**OSCAR** [S16]
- Annotations are CC0. The text is subject to the CC ToU.
- The HF repos are gated: `oscar-corpus/community-oscar` and `oscar-corpus/OSCAR-2301`, the
  latter with manual approval [S16b].
- Up to 151 languages, zstd JSONL. **Fields: `content`, plus `warc_headers` (includes the
  target URI, i.e. the URL), plus `metadata`.** The metadata includes fastText language ID,
  quality warnings, and **`categories` from a URL blocklist** (a crude topic and adult signal).
- The page gives the newest dump as 2024-38 (45 dumps), but the date shown ("2027/11/14") and
  the dump count are inconsistent. **UNVERIFIED.**

**HPLT** (High Performance Language Technologies) [S17, S18]
- **v3.0, July 2025:** packaging CC0 (HPLT does not claim the text). 198 language–script pairs.
  About 50 TB compressed; 13.5 T non-English tokens (Gemma-3 tokenizer).
  - ind_Latn: 176 M docs, 142 B tokens.
  - eng_Latn: 18.1 B docs, 16.3 T tokens.
  - por, vie, and tha counts are not captured. **UNVERIFIED.**
- Sources: Internet Archive plus CC crawls, so it is not a pure CC derivative.
- **Each document has a URL field `u`**, timestamps, language predictions, quality scores, and
  **web-register labels** (Turku register classifier; ind and eng have them). Register labels
  give a "format/genre" axis that complements topic.
- v2.0: 193 languages, about 21 B docs deduplicated; ind: 98 M docs in the cleaned set.
- On HF, `HPLT/HPLT3.0` and `HPLT/HPLT2.0_cleaned` are ungated, cc0-1.0. [S19]
- Bulk download uses `wget -i <lang>_map.txt` from data.hplt-project.org.
- A v4.0 page exists in the site navigation but its contents could not be read. **UNVERIFIED.**

**MADLAD-400** (`allenai/MADLAD-400`) [S21]
- The YAML header says ODC-By, but the card body says CC-BY-4.0. The two conflict.
- 419 languages, built from all CC snapshots up to 2022-08-01, with `clean` and `noisy` versions.
  - pt: 124 M docs clean.
  - id: 38 M.
  - vi: 55 M.
  - th: 17.4 M.
  - en: 1.5 B.
- **No URLs:** the records contain only `{"text": ...}`. I checked this by reading the first
  record of `data/pt/pt_clean_0000.jsonl.gz`.
- The data is document-level and fully deduplicated. Files are large jsonl.gz shards (about 3 GB

- **Not usable for the URL/domain caching experiments.**

Recommendation:
- **Main page source:** Common Crawl (columnar index + WARC) for anything needing raw HTML,
  URL/domain stratification, or latency replay.
- **Fast, clean, URL-bearing text samples:**
  - **FineWeb** (en)
  - **FineWeb-2** (pt, id, vi, th)
  - HPLT v3 as an independent second source that also has register labels.
- Avoid MADLAD-400 (no URLs). Avoid FineWeb-Edu as a general sample (topic bias).
- The cleaned corpora apply quality filters that change the topic mix (for example, they drop
  short product or list pages). Raw CC better matches what an ad categorizer actually sees.

Quality and speed evidence:

1. **Bevendorff, Gupta, Kiesel, Stein, "An Empirical Comparison of Web Content Extraction
   Algorithms", SIGIR 2023** [S24, S25].
   - Setup: eight human-labeled datasets combined (3,985 pages), 14 extractors plus 5 baselines,
     scored with ROUGE-LSum.
   - Mean F1:

     | Extractor | Mean F1 |
     |---|---|
     | Trafilatura | **0.883** (best single extractor) |
     | Readability | 0.861 (best median 0.970, most robust across complexity levels) |
     | Resiliparse | 0.859 |
     | DOM Distiller | 0.858 |
     | Boilerpipe | 0.834 |
     | Goose3 | 0.810 |
     | jusText | 0.759 |
     | html_text baseline | 0.683 |

   - Ensembles scored up to 0.899.
   - "No single extractor performs best on all types of web pages." Heuristic extractors beat
     neural ones.
   - Benchmark code: `chatnoir-eu/web-content-extraction-benchmark` (Apache-2.0).
2. **Trafilatura's own evaluation** (run dated 2026-10-02; 990 mostly German documents) [S26].
   - F-score:

     | Extractor | F-score |
     |---|---|
     | trafilatura 2.3.0 standard | 0.926 |
     | magic-html | 0.889 |
     | jusText | 0.862 |
     | readability-lxml | 0.853 |
     | resiliparse | 0.811 (precision 0.705, recall 0.955) |
     | goose3 | 0.810 |

   - Relative time against a baseline: resiliparse 0.3x; trafilatura 2.0–3.1x; readability-lxml
     3.0x; goose3 10.6x.
   - The author of trafilatura ran this benchmark.
3. **ScrapingHub article-extraction-benchmark** (MIT; repo archived 2026-06) [S27]. Article body
   F1:

   | Extractor | F1 |
   |---|---|
   | trafilatura 2.0.0 | 0.958 |
   | newspaper4k | 0.949 |
   | readability | 0.922 |
   | dragnet | 0.907 |
   | goose3 | 0.896 |
   | boilerpipe | 0.860 |
   | html-text | 0.665 |

4. **DCLM** (Li et al. 2024, arXiv 2406.11794, App. K) [S20].
   - Profiled 10 WARC files (about 900 k pages).
   - Throughput per core: **resiliparse 4.55 MB/s** against **trafilatura 0.56 MB/s**, about
     8x faster.
   - Downstream LM quality was similar, and both beat WET by at least 2.5 CORE points.
   - resiliparse keeps about 10% more text.
5. **WCXB** (Foley, arXiv 2605.21097, May 2026; CC-BY-4.0) [S28].
   - 2,008 pages across 7 page types (articles, forums, products, listings, …). Mostly English.
   - Dev F1 and speed:

     | Extractor | F1 | Speed |
     |---|---|---|
     | Resiliparse | 0.797 | 28 ms/page |
     | Trafilatura | 0.791 | 97 ms/page |
     | Readability | 0.674 | 785 ms/page |
     | Neural (ReaderLM-v2, 1.5 B) | — | ~10 s/page on A100 |

   - On articles, all top systems score about 0.93. They split apart on product and listing pages.
   - Caveat: the author also wrote rs-trafilatura, which tops the table at 0.859 F1 and 44 ms.
     Timings come from the author's own hardware.

Implications for this project:
- **Background labeling and training data:** trafilatura gives the best average quality.
  resiliparse is about 8x faster with higher recall. Topic classification tolerates some
  boilerplate, so resiliparse is likely good enough. That is a hypothesis to test: compare
  student F1 on trafilatura vs resiliparse text.
- **End-to-end latency benchmark:** extraction alone costs about 28–100 ms/page (WCXB numbers),
  roughly 100x the sub-ms inference target. Report it as its own stage. Also benchmark
  "title + meta description + URL only" as a near-free input.
- Benchmarks are mostly English or German. No PT, ID, VI, or TH extraction benchmark was found.
  Thai has no spaces between words, so word-based heuristics (e.g. jusText stoplists, which do
  ship for many languages) may behave differently. **UNVERIFIED how much this matters.**

## 4. Practicalities: fetching pages for the latency benchmark

**Robots and terms:**
- RFC 9309 (Robots Exclusion Protocol, Sept 2022, standards track) [S52]:
  - Fetch `/robots.txt` first and match user-agent groups case-insensitively.
  - Don't use a cached copy older than 24 h.
  - On 4xx, everything is allowed.
  - On 5xx (unreachable), assume a full disallow.
  - Follow at least 5 redirects; parse at least 500 KiB.
  - Robots rules are "not a form of access authorization", so site terms of service still apply
    separately.
- Recommended practice for any live fetching:
  - Set a descriptive `User-Agent` with a contact URL, and honor robots.txt for that agent and
    `*`.
  - Send at most about 1 request per host every few seconds, never in parallel to the same host.
  - Skip sites whose terms of service forbid automated access. Fetch only the URL list; don't
    crawl outward.
  - Don't store or republish full text beyond the benchmark.

  These are general good-practice judgments, not taken from a single source.
- CC ToU also says crawled content may carry its owners' terms [S9]. The CC
  `robotstxt` subset gives the robots.txt CC saw at crawl time, which is useful to pre-filter
  the URL list. [S2, S5]

**Splitting network time from processing time:**
1. **Fixed URL list from Common Crawl:**
   - Pick N URLs from the columnar index (stratified by language, TLD, and domain; one URL per
     domain to avoid hammering hosts).
   - Store the URL list together with `warc_filename` / offset / length, and publish the list
     for reproducibility.
2. **Offline replay (processing only):**
   - Pull the exact WARC records with HTTP range requests from `data.commoncrawl.org` and keep
     them locally.
   - Time `parse → extract → infer` on the local bytes using `warcio` (Apache-2.0) or `fastwarc`.
   - This gives the deterministic, network-free number.
3. **Local HTTP replay (server path without the internet):**
   - Serve the same records through `pywb` (GPL-3.0; fine for local tool use) or a tiny static
     server.
   - Run the full HTTP client path against localhost. This isolates client, TLS-less HTTP, and
     parsing overhead.
4. **Live fetch (real network):**
   - Re-fetch the same URLs politely (robots honored, low rate) and record DNS, connect, TTFB,
     and download separately.
   - Expect failures, redirects, and changed content. Report the success rate.
   - Run it once and from a known location, since results depend on geography.
5. Optional popularity-weighted URL lists: the **Tranco** top-1M list (daily, research
   ranking) [S53]. It has no explicit license, and one upstream source (Cloudflare Radar) is
   CC BY-NC. **UNVERIFIED for redistribution.** The CC index alone is the simpler choice.
